# T21a — Fundação do front e guia de design

## O que foi feito
`docs/design.md` define o assunto, a paleta (cinco cores nomeadas mais três derivadas, claro e escuro), a tipografia, o espaçamento e a representação visual de cada estado de validação e de atualização. O front passou a ter Tailwind CSS 4 com esses tokens em `src/index.css`, React Router com as rotas `/entrar`, `/`, `/conversas/:id`, `/carteira`, `/dados` e `/aviso-legal`, TanStack Query e o cliente Supabase (`src/lib/supabase.ts`).

Há um layout base (navegação inferior em 360 px, lateral a partir de 768 px, alternador de tema sistema/claro/escuro), os componentes de carregando, vazio e erro, e os selos `StatusBadge` e `FreshnessBadge`, que cobrem os nove estados com ícone, texto e borda própria. `public/_headers` traz a política de segurança de conteúdo e `public/_redirects` o fallback das rotas. As telas são marcadores ("ainda não foi construída"); as reais vêm de T21b a T21f.

## Por que foi feito assim
- Estética (skill `frontend-design`): o primeiro plano era creme, serifa e terracota, o padrão apontado pela skill. Foi trocado por papel cinza-esverdeado e azul-caneta, com o selo de conferência como elemento marcante. Está registrado em `docs/design.md`.
- Rotas privadas ficam sob `RequireAuth`, que redireciona para `/entrar` sem sessão e mostra erro (não a tela) se a sessão não puder ser verificada.
- Só o `Button` do shadcn/ui foi adicionado, porque é o único usado (E8). Foi escrito à mão no formato do shadcn, sem rodar o CLI, que precisa de rede.
- Fontes servidas do próprio domínio via `@fontsource-variable/*`, por causa da CSP.
- Sem variáveis `VITE_*`, o cliente Supabase aponta para `127.0.0.1:54321` com chave fictícia; as chamadas falham e as telas tratam como erro.

## O que foi descartado
Google Fonts (a CSP bloquearia e há dependência de terceiro); biblioteca de estado global (E18); `baseUrl` no tsconfig (removido no TypeScript 7, usa-se só `paths`).

## Arquivos principais
- `docs/design.md`: guia de design.
- `frontend/src/index.css`, `frontend/vite.config.ts`, `frontend/tsconfig.app.json`: tokens, plugin Tailwind e alias `@`.
- `frontend/src/App.tsx`, `src/routes/AppRoutes.tsx`: provedores e rotas.
- `frontend/src/features/auth/`: sessão (`api.ts`, `SessionProvider`, `sessionContext`) e `RequireAuth`.
- `frontend/src/components/layout/`, `state/`, `status/`, `ui/button.tsx`: layout, estados e selos.
- `frontend/public/_headers`, `_redirects`.
- Testes: `src/App.test.tsx` (redirecionamento, sessão, erro, rotas públicas) e `src/components/status/StatusBadge.test.tsx`.

## Como conferir
Em `frontend/`: `npm run lint`, `npm run typecheck`, `npm test` (6 testes) e `npm run build`. Na raiz: `bash scripts/ci/check_guardrails.sh`.

## Limitações e pontos de atenção
- `bash scripts/ci/check_bundle.sh frontend/dist` FALHA: o regex `sb_secret_` casa com o código do `@supabase/supabase-js`, que contém o prefixo literal em `startsWith('sb_secret_')` (não é chave). Corrigir exige alterar o script de CI, por exemplo para `sb_secret_[A-Za-z0-9_-]{20,}`, como já faz `check_guardrails.sh`. Não alterei o script; fica para o autor decidir. Sem isso, a CI do front falha.
- Contraste (4,5:1) e capturas de tela em 360 px e nos dois temas não foram verificados em navegador neste ambiente.
- O alternador de tema usa `localStorage`; se indisponível, vale só na visita.
- O link "Aviso legal" do rodapé só aparece nas rotas privadas.
