# Política de segurança

## Como relatar uma vulnerabilidade

**CANAL A DEFINIR PELO AUTOR.**

Este arquivo ainda não tem um canal de contato privado. O autor do projeto precisa escolher um e preencher esta seção antes de o repositório ser divulgado.

Uma opção é ativar o relato privado de vulnerabilidades do GitHub (*Private vulnerability reporting*, em Settings > Code security) e indicá-lo aqui.

Até o canal ser definido, **não publique detalhes de uma vulnerabilidade em issues ou pull requests públicos**, e nunca inclua credenciais reais em um relato.

## Escopo

Aplicação pessoal em fase inicial, mantida por uma pessoa. Não há prazo garantido de resposta.

## Segredos

Se você encontrar uma credencial no repositório, trate-a como comprometida: o autor deve revogá-la e trocá-la, e não apenas apagar o arquivo do histórico.
